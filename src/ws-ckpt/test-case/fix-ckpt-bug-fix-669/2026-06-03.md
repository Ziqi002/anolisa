## 为什么加

这是 **issue#669 的正式收口分支**，并且**直接修复了上一轮（2026-06-02）`fix-ckpt-bug-fix-615/2026-06-02` 用例 3.10 标注的已知缺陷**：

> 旧缺陷：commit `5bc4e2a` 声称 cwd 守卫覆盖 `init/rollback`，但 `guard_cwd_occupants` 只接入了 `init`（`workspace_mgr.rs`），`rollback` 路径未调用。

本分支 `ef4c0dc` 把守卫真正接入了 **rollback** 路径（`snapshot_mgr.rs` 在 rollback 前调用 `guard_cwd_occupants`），因此本用例的核心是 **回归验证该缺陷已修复**（旧的「有意 FAIL 探针」在本分支源码上应转为 PASS）。

四个 commit 共同完成了「cwd 占用拦截从 skill 提示层下沉到 daemon 层」的架构调整：

1. **`5f3a6ac` 优化拒绝提示**：hermes 插件 `__init__.py` / `tools.py` 把 cwd 拒绝信息结构化（`_cwd_inside_workspace_reason` 携带 cwd/workspace，返回 `tuple[bool, str]`）。
2. **`ef4c0dc` daemon /proc cwd 占用守卫（核心）**：扫描 `/proc/*/cwd`，借 `/proc/self/mountinfo` 派生 bind-mount 别名；**fail-closed**（扫描失败即拒绝）；跳过 `(deleted)` 孤儿 cwd；新增错误码 `CwdOccupied` / `CwdScanFailed`；**init 与 rollback 都接入守卫**；recover 有意不守卫（终端操作，CLI 层 WARNING 说明）。
3. **`247d4dd` RPM 打包收口**：`%dir /etc/ws-ckpt`（卸载时干净移除配置目录）；`%post` 仅当 `/usr/bin/ws-ckpt` 确属旧 ws-ckpt 包（`rpm -qf` 校验）才移除，避免误删。
4. **`cf54782` skill 层去重**：daemon 已统一拦截 cwd，SKILL.md 移除冗余的「禁止 workspace 为 cwd / cwd 父路径」前置告警与 cwd 查询块，并把 skill 标注为仅 Linux。
