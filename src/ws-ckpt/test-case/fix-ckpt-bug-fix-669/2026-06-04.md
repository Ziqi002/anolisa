## 背景

2026-06-03 已覆盖 4 个领先 commit（cwd 守卫核心）。本次新增第 5 个 commit `32dd1d8`，它修复了 plugin error mapper 中 daemon 的 anyhow chain 内部 io error 字符串泄漏到外层 matcher 的问题：

- `CwdScanFailed` 包裹 ENOENT/EACCES 时，generic "not found" / "permission" matcher 先匹配到，导致报给用户 "Snapshot not found" 而非正确的 "cwd scan failed"
- hermes `checkpoint_manager.py`：移除不可达的 "not initialized" 分支，增加 "already exists" / "active write" / "insufficient" matcher，把 "daemon"/"connection" 替换为精确 "daemon is not running"/"starting up"，把 "not found" 精确化为 "snapshot" / "workspace" 子串匹配
- openclaw `btrfs-manager.ts`：增加 "daemon is not running"/"starting up" matcher，把原有 "not found" + "snapshot/workspace" 双条件搬到 cwd matcher 之后

关键修复效果：**cwd scan 失败**不再被误报为 "Snapshot not found"。
