## 为什么加

该 commit 给两个 runtime plugin（hermes / openclaw）引入了**按工作区维度的 cron 定时快照**能力：
用户可配置 `cronSchedules`（每个 workspace 一组 5 字段 cron 表达式），plugin 会把
`ws-ckpt checkpoint -w <ws> -i "cron-$(date +%s)" ...` 写入用户 crontab。会话内对 cron 表达式做
增删改（`add` / `remove` / `set`），workspace 切换时迁移旧条目，并用文件锁防止并发改 crontab 的 TOCTOU。

这是一条全新的用户可见特性，且改动横跨 hermes(Python) 与 openclaw(TypeScript) 两套实现，逻辑彼此镜像。
若解析/校验/crontab 行命令构造有偏差，会导致：写出非法 cron 行、误删别的 workspace 的条目、
或注入风险（workspace 路径未正确 shell 转义）。因此需要静态契约断言 + 纯函数动态行为验证双重把关。

## 加了什么测试

脚本 `2026-06-11.sh` 分为多个 Section：

1. **hermes cron.py 静态契约**：模块存在、关键导出（`validate_cron_expr` / `parse_schedules_update` /
   `CrontabManager`）、5 字段 cron 正则、shell 单引号转义 `'\''`、checkpoint 行模板关键片段、
   flock 互斥（`fcntl.flock` + `LOCK_EX`）、`migrate` / `sync_with_retry` / `list_installed` 等方法。
2. **hermes config.py 契约**：`cron_schedules` 字段（`Dict[str, List[str]]`）、yaml 加载时对非法表达式
   过滤并打印告警、不提供 env 覆盖。
3. **openclaw cron.ts 静态契约**：与 hermes 镜像的导出、正则、`shellQuote`、`buildCronLine` 模板、
   `withLock`（mkdir 锁目录 + 超时降级）、`parseSchedulesUpdate` 的 add/remove/set 分支。
4. **openclaw commands.ts**：新增 `runCrontab`（input 走临时文件，因 execFile 不支持 stdin）。
5. **manifest / 配置 schema**：`openclaw.plugin.json` 新增 `cronSchedules`（object，additionalProperties=array of string）；
   hermes tools.py 暴露 `cronSchedules` 配置键与用法说明。
6. **动态：hermes cron 纯函数**（需 python3，缺则 SKIP）：
   - `validate_cron_expr`：合法 `0 * * * *` → True；4 字段 / 空串 → False。
   - `parse_schedules_update`：`add "0 * * * *"` 追加；重复 add 不重复；`remove` 不存在报错；
     非法表达式 add 报错；`set '["0 0 * * *"]'` 覆盖；`set` 非数组报错；未知 sub-action 报错。
7. **动态：openclaw cron 纯函数**（需 node，缺则 SKIP）：从 `dist/` 或用 tsc 无法编译时退回，
   对 `validateCronExpr` / `parseSchedulesUpdate` 做与 hermes 等价的断言（验证两套实现行为一致）。
