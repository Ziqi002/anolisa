## 为什么加

本分支尚未合入 main，围绕一个核心安全主题展开：**防止快照 symlink 交换悄悄令存活进程的 cwd 失效**。三个 commit 从三个层面加固：

1. **Skill 增加 cwd 查询方法（e5966cc）**：SKILL.md 新增「cwd 查询方法」段落，要求 agent 用 `readlink /proc/$PPID/cwd` 获取宿主进程真实 cwd（不受 shell `cd` 或 Primary working directory 影响），杜绝靠猜测判断 cwd 是否落在 workspace 内。
2. **优化拒绝提示（2890b2a）**：hermes 插件 `__init__.py` / `tools.py` 重构 cwd 拒绝逻辑，新增 `_cwd_inside_workspace_reason()` 与返回 `(inside, cwd)` 元组的 `_cwd_inside_workspace()`，让拒绝信息携带具体 cwd 与原因，便于 agent 把问题转达给用户。
3. **daemon 端 /proc cwd 占用守卫（5bc4e2a，issue#669）**：在 daemon 真正执行 init/rollback 前，扫描 `/proc/*/cwd`（含通过 `/proc/self/mountinfo` 推导的 bind-mount 别名），一旦发现有进程 cwd 落在 workspace 内即**拒绝执行**。设计要点：
   - **fail-closed**：`/proc` 扫描失败时拒绝操作（而非放行），新增可重试错误码 `CwdScanFailed`。
   - **占用拒绝**：确认有占用进程时返回硬错误码 `CwdOccupied`（不可重试）。
   - **跳过孤儿 cwd**：`/proc/<pid>/cwd` 末尾为 ` (deleted)` 的项已经损坏，跳过且必须在匹配器之前跳过（否则 `"/ws/src (deleted)"` 会误命中前缀）。
   - **recover 故意不守卫**：recover 是终端操作（CLI ConfirmationRequired），文档化为不在守卫范围。
   - **跨 namespace 占用**：明确为 out of scope。

## 缺陷发现（DEFECT，待开发确认）

**标题**：`5bc4e2a` 的 /proc cwd 占用守卫只接入了 `init`，未接入 `rollback`，与 commit 声明不符。

- **严重级别**：中（功能缺口 / 与提交说明不一致）。`init` 已受保护，但 `rollback` 同样会触发 symlink 交换，理应同等防护。
- **证据**：
  - commit message：`feat(ws-ckpt): add /proc cwd occupant guard for init/rollback (issue#669)`，正文写明「Refuse **init/rollback** when any process has its cwd inside the workspace」。
  - `git grep -n guard_cwd_occupants 5bc4e2a -- src/ws-ckpt` 仅命中两处：定义 `util.rs:359`、调用 `workspace_mgr.rs:247`（即 `init`）。
  - `snapshot_mgr.rs` 的 `rollback()` 仅有注释 `// 2. Write lock: validate snapshot → cwd guard → execute rollback`，但函数体内**没有任何** `guard_cwd_occupants` 调用；同 diff 还删除了原 `let _abs_path_str = ws.path...` 行。
  - 后端 `btrfs_base.rs` / `btrfs_loop.rs` 的 `rollback()` 也未调用守卫/占用扫描。
- **预期**：`rollback` 路径在执行 backend 交换前应调用 `guard_cwd_occupants(&ws_abs_path)`，与 `init` 行为一致。
- **实际**：`rollback` 完全不检测 cwd 占用，存在「rollback 时 symlink 交换悄悄使存活进程 cwd 失效」的回归风险（正是 issue#669 想防住的场景）。
- **处置**：本角色仅出具缺陷报告与可复现断言（用例 3.10 故意断言期望接入守卫，当前在分支源码上会 **FAIL**），不修改业务代码。修复需移交开发：在 `snapshot_mgr::rollback` 拿到 workspace 绝对路径后、调用 `state.backend.rollback(...)` 之前补一次 `guard_cwd_occupants`。

> 注：用例 3.10 的 FAIL 是**有意为之的缺陷探针**。其余用例应全部 PASS（在 `fix/ckpt/bug-fix-615` 分支源码上）。在 ckpt-test 等旧源码工作区，整脚本经 `tc_require_branch` 守卫整体 SKIP。
