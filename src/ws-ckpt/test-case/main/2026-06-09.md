## 加了什么测试 / 期待结果

脚本 `2026-06-09.sh` 分为 6 个 Section，全部为**静态源码契约断言**（Mac/Linux 均可跑），
另含可选实跑段（需二进制时 SKIP）。脚本顶部用 `tc_require_branch "..." "main"` 守卫：
在 ckpt-test 等不含 v0.3.3 源码的分支上整体 SKIP，到 main / 已合并环境上才执行。

### Section 1 — common 协议：versioned JSON schema（`0e04853`）
- **为什么**：插件把 daemon 的 JSON 当契约消费，schema 版本串一旦漂移而不报错，
  旧插件会把新结构误判为 "disabled"（正是 openclaw 的原始 bug）。必须钉住三个版本常量。
- **测什么**：`common/src/lib.rs` 含 `WORKSPACE_POLICY_JSON_SCHEMA = "ws-ckpt-policy/v1"`、
  `GLOBAL_CONFIG_JSON_SCHEMA = "ws-ckpt-config/v1"`、`OVERVIEW_JSON_SCHEMA = "ws-ckpt-overview/v1"`；
  新增 IPC 变体 `GetWorkspacePolicy`/`PatchWorkspacePolicy`/`ResetWorkspacePolicy`/
  `ReloadGlobalConfig`/`ReloadWorkspacePolicy`/`ConfigOverview`；类型 `WorkspacePolicy`/`EffectivePolicy`/
  `PolicyFieldOp`；`EffectivePolicy::is_disabled` 存在。
- **期待**：以上常量/类型/变体字符串全部命中（PASS）。

### Section 2 — CLI `config` 子命令重构（`0e04853`）
- **为什么**：`config` 的作用域语义变了——无 scope = 只读 overview，`-g` 全局，`-w` 局部，
  `--reset` 仅对 `-w` 合法且与所有 set flag 互斥。错误的 scope 组合必须在解析层拒绝。
- **测什么**：`cli/src/main.rs` 含 `struct ConfigArgs`、`short = 'g'`/`short = 'w'`、
  `ArgGroup::new("scope")`、`reset` 字段、`conflicts_with_all`、`handle_workspace_config_reset`、
  `handle_config_overview_view`、`--reset is only valid with -w/--workspace` 错误串、
  `unknown --format value` 错误串、三栏 effective/local/global 渲染。
- **期待**：全部命中（PASS）。

### Section 3 — daemon：per-ws 状态与并发安全（`0e04853`）
- **为什么**：per-ws 策略引入了新的并发面——同一 ws_id 的 init/adopt/recover 必须串行，
  recover 必须清空 per-ws index dir 以免同路径 re-init 继承陈旧元数据；reload 必须先 per-ws
  再 global 以保证"只多留、不误删"。
- **测什么**：`workspace_mgr.rs` 含 `lock_wsid`；`state.rs` 含 `WorkspacePolicy`/`policy_io_mu`/
  `wsid_lock`；workspace_mgr 在 policy.toml 读失败时以 `auto_cleanup=false`（不继承全局）注册的注释/逻辑；
  recover 清空 per-ws index dir 的注释（`Remove the entire per-ws index dir`）。
- **期待**：全部命中（PASS）。

### Section 4 — skill / plugin：辨识联合（discriminated union）解析（`44607ee`）
- **为什么**：插件必须 `ws-ckpt config -w <ws> --format json` 拿到自己 workspace 的策略，
  并用 parse-error / disabled / count / age 四态联合解析，**把 parse 失败和真正 disabled 区分开**
  （否则重演 openclaw "regex miss 误显示 disabled" 的 bug）；并信任 daemon 预计算的 `is_disabled`。
- **测什么**：
  - openclaw `config.ts`：联合类型 `parse-error`/`disabled`/`count`/`age`、schema 校验
    `root.schema !== "ws-ckpt-policy/v1"`、`is_disabled === true`、严格整数校验（拒 NaN/float/负数）。
  - hermes `tools.py`：`_POLICY_JSON_SCHEMA = "ws-ckpt-policy/v1"`、`_parse_workspace_policy_json`、
    四态 kind、信任 `is_disabled`、严格 int 解析。
  - `SKILL.md`：含 `config` 文档段、`-g`/`-w` scope 说明、`--format json`。
  - openclaw handlers：`unset` 恢复 inherit-global（删 policy.toml）的处理。
- **期待**：全部命中（PASS）。

### Section 5 — init 数据安全（`b6155bb` / `605a760` / `8952d60`）
- **为什么**：init 失败若误删/覆盖原始数据是不可逆的高危后果。本组确认 backend 采用
  "先 rename 成 `.pre-init-bak` 再迁移数据"、InPlace 用 `cp --reflink=always`（同盘 COW，
  备份全程不动），且对 foreign/leftover backup 主动 bail，对 EACCES/EIO 大声中止。
- **测什么**：`btrfs_base.rs`/`btrfs_loop.rs`/`btrfs_common.rs` 含 `.pre-init-bak`、
  `--reflink=always`、对 leftover backup 的 bail 逻辑、`restore_original_from_backup` 用
  `io::ErrorKind::NotFound` 区分"无备份"与其它 stat 错误。
- **期待**：全部命中（PASS）；`move_contents` 已被移除（不再出现于 btrfs_base.rs）。

### Section 6 — 锁粒度 / 原子写收尾（`822bfda` / `3c2f421` / `a60d468` / `d3089d3`）
- **为什么**：长耗时 fs 操作与 /proc 扫描不应持有 ws 写锁阻塞并发；状态持久化应原子写。
  这几条是上一轮 issue#669 cwd 守卫的并发收尾，回归确认守卫被移到写锁之外、写锁被合理降级、
  save_state 走 atomic_write。
- **测什么**：`common/src/persist.rs` 含 `pub fn atomic_write`（tmp+fsync+rename 原子写）；
  `snapshot_mgr.rs` 中 rollback 路径仍保留 `guard_cwd_occupants` cwd 守卫（已在写锁外，回归确认）。
- **期待**：全部命中（PASS）。
