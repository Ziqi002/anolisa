## 为什么加

main 自上次（2026-05-25，覆盖到 v0.3.0）后连续发布了 **v0.3.1** 与 **v0.3.2**，这 14 个 commit 已落入 main，是已合并的回归基线。其中部分修复（死代码清理、fswatch、cwd 拒绝、skill --force、插件自动加载）此前在 `feat/ckpt/bug-fix` 分支用例里测过，现在它们已合入 main，需要在 main 源码上建立**回归断言**；同时 v0.3.1/v0.3.2 还引入了若干 main 上的新增项。主要变更方向：

1. **OpenClaw 集成健壮性（7a208e6 / 13f51e1 / 2152a7d / 79fd8d3）**：规范 OpenClaw state dir 处理（`OPENCLAW_STATE_DIR`）、插件 `onStartup` 自动加载、显式 workspace 优先于 config、把 workspace 注册进 plugin config（否则 `openclaw config set` 无法识别）。
2. **cwd 父路径保护（3f66bbd）**：skill / hermes / openclaw 三处统一新增「workspace 不可是 cwd 或 cwd 父路径」规则；hermes 拒绝信息改为结构化 JSON（`retryable: False`）。
3. **卸载更彻底（f08a457 + uninstall 脚本）**：卸载 openclaw 时从 `openclaw.json` 的 `tools.alsoAllow` 移除 `ws-ckpt-*` 工具白名单；卸载 hermes 时从 `~/.hermes/config.yaml` 的 `plugins:` 块移除 ws-ckpt。
4. **新增只读探测脚本 detect-openclaw.sh**：检查 OpenClaw CLI / 插件安装状态 / 运行时二进制 / adapter 源可用性，二者齐备退出 0，缺一非零。
5. **死代码清理 + fswatch + skill --force（c6fb08d / 15ef957 / 6e8ad1a）回归**：移除 `btrfs_ops.rs`、CLOSE_WRITE 清 writing 标志、skill delete 强制 `--force`。
6. **standalone ANOLISA adapter 入口（3b7168d）**：scripts 新增独立 adapter 入口。
7. **版本与打包一致性（v0.3.1 / v0.3.2）**：Cargo/manifest/spec/CHANGELOG 全部对齐到 0.3.2。
