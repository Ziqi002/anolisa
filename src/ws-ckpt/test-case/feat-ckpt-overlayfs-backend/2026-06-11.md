## 为什么加

该分支为 ws-ckpt 引入**第三种快照后端 OverlayFS**（此前仅 `btrfs-loop` / `btrfs-base`），
通过 OverlayFS 多层叠加 + 未来的 DeltaFS 内核模块 ioctl 实现动态层切换，使快照不再依赖 btrfs。
改动横跨 common（`BackendType::OverlayFs`、`OverlayfsConfig`、`BackendError::LayerLimitExceeded`、
新 `ErrorCode::LayerLimitExceeded`、默认常量）、daemon（`backends/overlayfs.rs` 全新后端、
`backend_detect.rs` 注册、`dispatcher.rs` 错误 downcast 映射）、cli（layer-limit 友好错误提示）。

这是会改变后端选择与错误语义的结构性变更。关键风险点：
- 后端类型字符串解析（`"overlayfs"` → `BackendType::OverlayFs`）必须接通，否则配置静默回落 auto。
- **层数上限保护**：超过 `soft_layer_limit`(450) / `hard_layer_limit`(500) 时必须返回
  `LayerLimitExceeded`，否则内核 mount 会失败且无引导提示。
- dispatcher 必须把 `BackendError` downcast 成对应 `ErrorCode`，否则被吞成 `InternalError`。
- workspace 路径未 shell 转义会有注入风险（mount/rsync 命令构造）。

由于本机无 btrfs / 无 DeltaFS 内核 / 无 ws-ckpt 二进制，且 commit 名为 `temp`（WIP），
本轮以**静态源码契约断言**为主，不做 daemon 实跑。后续若分支成熟、具备 Linux+内核环境，
再补运行时层切换与上限触发的端到端用例。

## 加了什么测试

脚本 `2026-06-11.sh` 分为多个 Section：

1. **common backend 枚举与类型**：`BackendType::OverlayFs` 变体、Display 输出 `"overlayfs"`、
   `OverlayfsConfig`（data_root / soft_layer_limit / hard_layer_limit）、`BackendError::LayerLimitExceeded`。
2. **common 常量与 ErrorCode**：`DEFAULT_OVERLAYFS_DATA_ROOT=/var/lib/ws-ckpt/overlay`、
   `DEFAULT_OVERLAYFS_SOFT_LAYER_LIMIT=450`、`DEFAULT_OVERLAYFS_HARD_LAYER_LIMIT=500`、
   `ErrorCode::LayerLimitExceeded`、`DaemonConfig.overlayfs_config`、`BackendConfig.overlayfs`、
   `from_backend_type` 中 `"overlayfs"` 分支。
3. **daemon backend_detect**：`BackendType::OverlayFs` 注册分支、`OverlayfsBackend::new` 调用、
   `data_root` 默认回落到 `DEFAULT_OVERLAYFS_DATA_ROOT`。
4. **daemon overlayfs.rs 后端实现**：模块在 `mod.rs` 注册、`struct OverlayfsBackend`、
   层目录布局（base/upper/work/merged）、`layer_count`、`create_snapshot` 中
   hard/soft 双阈值检查返回 `LayerLimitExceeded`、DeltaFS ioctl STUB 注释、mount overlay 命令。
5. **daemon dispatcher 错误映射**：`downcast::<BackendError>`、`LayerLimitExceeded` → `ErrorCode::LayerLimitExceeded`。
6. **cli 友好错误提示**：`ErrorCode::LayerLimitExceeded` 分支提示 `ws-ckpt cleanup ... --keep`。
