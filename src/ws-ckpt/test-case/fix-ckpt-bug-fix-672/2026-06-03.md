## 为什么加

issue#672：snapshot id 会**直接作为路径组件**用于快照子卷命名。如果允许空白、`/`、`\`、`.`、`..` 这类 id，会生成 `delete` / `rollback` 路径**无法寻址**的快照记录（轻则记录孤立、重则路径穿越写到 workspace 之外）。本 commit 在 **clap 解析层**（`checkpoint -i/--id` 的 `value_parser`）就拒绝非法 id，把问题挡在最前端。

变更落点：`cli/src/main.rs`

1. 新增 `snapshot_id_value_parser()`：空白（`trim().is_empty()`）拒绝；含 `/`、`\`、或等于 `.` / `..` 拒绝；其余放行。
2. `checkpoint` 子命令的 `id` 参数挂上该 `value_parser`。
3. 配套单元测试（拒绝空白、拒绝路径分隔符、接受正常 id）——**注意：单元测试是开发侧产物，本 QA 不依赖/不运行它**，QA 用独立的 CLI 行为断言与静态断言覆盖。
